# 装配实验室（浏览器验证 harness）

本目录是**常驻的浏览器验证套件**：用 Playwright 打开装配页跑断言，覆盖「装配页能不能
装起来、装得对不对」这一类问题。它在仓库里（而不是在某个 worktree 的 `.dev-host/` 里）
的原因是一条铁律——**验证集里必须有「底座契约完备性」断言**（见 `AGENTS.md`）：0.1.6 的
`usePanelInfo` 事故就是「底座漏了一条官方下发的契约、真运行里才炸」的典型，这类断言必须
每次改装配都能重跑，而不能随着 worktree 被删掉。

## 它验的是什么（和另外两条验证线的关系）

| 线 | 跑法 | 验什么 | 快慢 |
| --- | --- | --- | --- |
| **浏览器验证**（本目录） | `npm run verify:lab` | 装配页在**普通浏览器**里能不能装起来、槽位有没有内容、渲染/交互/外观对不对。页面用仓库真实模块构建，数据面是**实验室自起的隔离实例**（见下），宿主侧是假宿主 | ~50 秒，第一道 |
| **VS Code 验证** | `scripts/dev-ui-test.sh` | 真 VS Code webview 宿主层：CSP 差异、剪贴板、原生菜单、多 webview 生命周期。慢，是**最终准绳** | 分钟级 |
| **沙盒**（`test/sandbox/`） | `test/sandbox/run-sandbox.sh` | code-server 里装真插件 vsix 做宣发截图/人工核对 | 分钟级 |

三者不互相替代：本目录跑绿的改动仍可能需要 VS Code 验证（尤其碰宿主行为时），反之亦然。

## 隔离实例（默认跑法连的就是它）

**名词，先说清楚再用**：

- **隔离实例** = 实验室**自己起**的一台 `dsh web`：`DSH_HOME` 指向本次运行新建的临时目录、
  端口现取一个空闲的、`--no-open`（不起浏览器窗口）。整轮跑完（或被 Ctrl-C、或异常退出）
  一律**按 PID** 收掉、临时目录删掉。**用户的 `~/.dsh` 一个字节都不动**，用户日常那台实例
  （缺省 3080）全程只被**只读**探测两次（跑前一次、跑后一次，见 R-06）。
- **播种** = 整轮开始前，经**官方 RPC** 往这台实例里写入真数据（工作区、各种状态的会话、
  归档记录），代码在 `seed.ts`，清单在下一节。

为什么默认跑它（2026-09-18 的用户拍板，见 #177）：以前默认对着用户日常实例跑，只能**只读**，
于是需要数据的判据要么吃当天数据（一天撞好几次假红，见 #148 / #116），要么在页面里自造帧
（`dataset.ts`），两头都别扭；探针误点一个写类控件还会改到用户的真实状态（#163 的现场）。
自起一台之后**写操作自由**，判据可以用真数据算，共享实例上「别人正在写」的抖动也一并消失。

### 播种进实例的是什么（`seed.ts`）

| 造什么 | 怎么造 |
| --- | --- |
| 五棵真工作区 | 临时目录（建在本次运行的临时 `DSH_HOME` 里，收尾一起删）+ `workspace/create`。树里看到的顺序是**倒序**（新建的排最前），所以播种清单按倒序写，树里读起来是 `Lab-Alpha`（4 条会话）→ `Lab-Beta`（3）→ `Lab-Gamma`（3）→ `Lab-Delta`（2）→ `Lab-States`（特殊状态那一棵，排最后） |
| 空闲会话 | `session/create` + **真发一条提示词**（模型是本次现起的假端点，见下）+ `session/rename` 定标题。为什么必须真发：dsh 里 `blank: true` 的会话**不上树**（`pure/workspaceTreeView.ts` 的 `sessionVisible`），光建会话造不出行 |
| 各种状态 | 运行中 / 等审批 / 等回答 各一条，提示词见 `labLlm.ts` 的 `LAB_PROMPTS`，由假端点编排出来（真回合、真等待态，不是页内帧）。这三条在**树里最后一行那一棵**（`Lab-States`）里：活状态计数是它们贡献的，「取树上第一行当夹具」的套件才不会一上手就撞上一条跑着的会话；各自的持续时间由假端点决定（「运行中」那条按 400 块 × 3 秒推，整轮期间一直挂在运行态） |
| 归档 | 一条真 `workspace/archiveSession`（归档语义是真的），**在整轮播种里最先建**——`session/list` 是新建在前的倒序，于是它排在清单末尾，不会被「取第一条能用的会话」的动作挑中（归档会话在页面上打不开，客户端渲染的是首屏空态，实测过） |
| 空白会话 | 每棵工作区一条（不上树）：官方客户端挂载时会去「最近的工作区」找一条空白会话落脚，没有现成的它会**自己新建一条**（那是往实例里写，且每开一页写一条） |
| 页面语言 | 实例自己的设置文档（`DSH_HOME/settings.yaml`，起进程前写好）里 `locale.preference: zh`——语言是判据的环境输入，钉死它判据才不吃语言 |
| 模型 | 同一份设置文档把 provider 指到本次现起的假端点（`test/mock-llm/` 的 `createMockLlm`，零依赖、只监听 127.0.0.1），`apiKeyEnv` 的值在起进程时给 |

一句话：**能在实例里真造的都真造**；页内夹具（`dataset.ts`）只在「要造官方回执的特定形状」
时才用（例如故意造坏形状测失败路径），套件要夹具数据就自己显式声明（F-41 与 F-58 就是）。

### 播种账目与「套件怎么认行」

`seed.ts` 把造出来的东西作为一份账目返回（`LabSeed`：工作区、会话、归档集合，每条会话带
`state`），挂在 `LabGateway.seed` 上、并打进运行日志——它是「这台实例里到底有什么」的
事实源，排查播种问题时先看它。**特殊状态一律放在最后一棵工作区**（`Lab-States`）：活状态
计数是这些会话贡献的，放最后才不会把别人那棵工作区的读数顶高。

套件认行的方式是**读页面/网关上的真数据**（树上的行、`session/list` 的字段），不是认死
某个 id——这正是 #177 想要的收敛方向（以前的判据要么吃当天数据，要么在页面里自造帧）。
需要「这一组必须是干净的」这类前提时，按页面上的读数判（见 F-52 挑目标分组的那一段）。

## 和每日上游探针（`clientContract.mjs`）的分工

两个面都在管「官方变了」，但一个离线、一个在运行期，红了要去做的事也不一样：

| 谁 | 跑法 | 查什么 | 红了说明 |
| --- | --- | --- | --- |
| 每日上游探针 | CI 每天 04:00 跑 `node scripts/dsh-upstream-watch/probe.mjs`，客户端契约面在 `scripts/dsh-upstream-watch/clientContract.mjs` | **离线扫官方 bundle**：官方前端段还能不能切开、slot / root hook / 我们取用过的字段名**还在不在**（名字层面） | 官方动了名字——先按失败信息里的期望出处去核对官方源码，再改我们的取用路径 |
| 本目录的 F-10 / F-11 | `npm run verify:lab`（本机；网关由实验室自己起） | **运行期**：F-10 看 cordis scope 的**状态**（四棵树零 FAILED，靠页面里的 fiber 探针），F-11 看**我们自己的 block list 与当天官方清单对不对得上** | 名字还在但**装起来不活**（F-10），或清单漂移导致过滤静默失效（F-11）——这两种探针都看不见：探针不跑页面，也读不到我们的 block list |

一句话：**探针管名字在不在（离线、每天、不需要网关），实验室管装起来活不活、清单还对不对得上（运行期、真网关、改装配必跑）。**

## 跑法

```bash
npm run verify:lab                      # 全量：build + 自起隔离实例（播种真数据）+ 全部套件 + ledger + HTML 报告
npm run verify:lab -- --suite F-01      # 只跑契约完备性
npm run verify:lab -- --gateway http://127.0.0.1:3080   # 连外部实例（人工排查；只读）
npm run verify:lab -- --headed --keep   # 开有界面的浏览器，跑完留服务器，人工点页面
```

**零参数就是合入门禁那一条跑法**：自起一台隔离实例、播种、整轮对着它跑。
两道额外的口子：

- `--gateway <url>`（或环境变量 `LAB_GATEWAY`）连**外部实例**，人工排查用；那时不自起
  实例、不播种，按既有口径**只读**对待（R-06 改判那台实例的会话数跑前跑后一致）。
  给别的端口/手工起的实例还要 `--token <token>`（`LAB_TOKEN`）。
- `--empty` **已退役**：那套跑法就是现在的默认跑法，只是实例里会播种真数据。老参数仍然认，
  但直接报错退出（免得有人以为跑的是空实例）。

前置条件（一条）：`npm run build` 过（`verify:lab` 自己会先跑）。自有插件的 bundle 在
`dist/assembly/plugins/`，页面要靠它装配。**不再需要本机有在跑的 dsh 网关**——实例由实验室
自己起；用户日常那台只被只读探测两次（探不到就如实记一条事实，见 R-06）。

环境变量：`LAB_GATEWAY`（外部实例地址）、`LAB_TOKEN`（外部实例的 token）、`LAB_PORT`
（实验室端口；**缺省时先试 3179、被占用就自动退到随机空闲端口并打印实际地址**——并行跑多条线时不用再自己记得给 `LAB_PORT`；显式给值时占不到就按人话报错退出，不会偷偷换端口。见 #194）。全部参数见 `node test/assembly-lab/verify.ts --help`。

### 套件判据不许依赖运行环境（#162 立，硬约束）

写套件时，凡是「这台机器上碰巧是什么样」的东西，**都不许进判据**：

- **数据**（有几棵工作区、几条会话、它们叫什么、属于哪个分组）→ 默认跑法**在实例里播种**
  （`seed.ts`，见上一节），套件读的就是那份真数据；需要「自己声明一份合成数据」的少数几档用
  **页内数据集夹具**（`dataset.ts`）：`openTreePage(..., { dataset })` 显式声明——#177 起
  只有这一条路（以前还有「整轮统一装一份 `SIDEBAR_DATASET`」那条，随默认跑法换成播种退场了）。
  已经自己声明的：F-41（成员清单要一份自己控制的工作区清单）、F-58（添加工作区的收尾）。
  不声明 = 用实例里播种的真数据。
- **文案**（按钮、菜单、提示、读屏标签）→ 从插件词典读（`workspaceTree/locale.ts` 的 zh / en 两份）。
  断言里写死中文会在英文页面上假红——页面语言是环境输入。不过 #177 起隔离实例的设置文档
  **把语言钉成 zh**（`labGateway.ts` 的 `settingsYaml`），所以这一条在默认跑法下不再是变量；
  词典口径（`check.eqText` / `isText` / `hasText`）**照旧保留**：连外部实例时页面语言仍可能
  是 en，钉住的是默认那条跑法而不是判据的写法。
- **不要放宽判据来让它变绿**：这些事修的是**数据与文案的来源**，不是期望的松紧。真做不到自控的
  少数几档，改成「记事实 + 只判关系量」，并在注释里写明为什么。

### 自己起网关时必须给独立的 `DSH_HOME`（硬规矩）

这是默认跑法的做法（`labGateway.ts` 就是这么做的），也是人工排障时自己起网关的规矩。
**自己起的那个必须带独立的 `DSH_HOME`**：

```bash
TMP=$(mktemp -d /tmp/dsh-lab-home.XXXXXX)
DSH_HOME=$TMP dsh web --host 127.0.0.1 --port <挑一个没占用的> --no-open
# 跑完按 PID 收掉自己的那一个，并删掉 $TMP
```

**为什么不带 `DSH_HOME` 就是错的**：不带就等于**和用户共用同一份会话库**（`~/.dsh`）。dsh 的会话
日志是**单写者、跨进程**——实验室每跑一轮都会真的打开会话、把它们**占住写句柄**，于是用户在
VS Code 里点同一条会话就会撞上「该会话正被另一个 dsh 占用」（#145 加的提示；2026-09-17 实测过
一次，机器上同时挂着 6 个残留网关，最长的活了 2 小时 26 分）。这一条同时是「不占用户的资源」
的延伸：**不占用户的资源**与「不写用户的数据」同等重要。

其它三条纪律（都来自实撞）：

- **按 PID 收网关**，别用 `pkill -f "dsh web"`：那会连用户自己的实例一起打断（实测发生过）。
- 收干净再走：跑完 `lsof -nP -iTCP:<你的端口> -sTCP:LISTEN` 确认没监听，临时 `DSH_HOME` 目录删掉。
- **别写 `~/.dsh/dsh-owned.json`**（那是扩展与用户实例的登记表）。

chromium 由 devDependency `playwright` 在 `npm ci` 时下载；如果没有（例如装依赖时跳过
了脚本），先跑一次 `npx playwright install chromium`。

## 干净 profile 那一档（#164）

上面那条前置条件（「本机有一个在跑的 dsh 网关」）**不够**：日常那台网关带着用户
profile 的全部补丁与历史数据，有些缺口在它上面永远看不见。#164 的现场就是侧栏树
的 block list 挡掉了官方 `ui-commands`，而官方 `ui-model-selection` 按服务名依赖它
提供的 `commandUi`——boot 的规矩是**一个条目没激活就整页抛错**，于是侧栏树整个挂
不上；可这台机器的日常 profile 里 `@dsh-one/dsh-llm-provider`（另一仓）的 bundle
patch 把 `ui-model-selection` 整行禁掉了，没人去等那个服务，本地怎么跑都是绿的，
只有**新装用户**会看到一片空白。

所以 F-55 这一档**自己起一台全新 `DSH_HOME` 的网关**再跑：`test/assembly-lab/freshGateway.ts`
用 `--port 0`（内核挑端口，不跟任何已知端口抢）、`--no-open`、`mkdtemp` 出来的临时
目录当 `DSH_HOME`（不碰 `~/.dsh`，也不写 `~/.dsh/dsh-owned.json`），收尾**按 PID**
`SIGTERM`/`SIGKILL` 并删掉那个目录——**不用 `pkill`**（`pkill -f "dsh web"` 会连用户
正在用的实例一起打断）。`--port 0` 与「收尾按 PID」这两条是硬要求，别为了省事改回固定端口。
（#177 起默认跑法也是「自起一台」，实现是 `labGateway.ts`——它与本文件的分工：默认那台要
**播种真数据、钉语言、挂假模型端点**，F-55 这台要的是**什么都没动过的干净 profile**，两者
判的是不同的事，各留各的。）

F-55 只钉**装载这一层**：三棵生产树挂得上、零 `waiting for service` / 零 FAILED、
零崩溃、零 pageerror，外加「侧栏树的 combo 里有 #164 放行的那两件」。它**不等于**
「整轮在空实例上也绿」——那是 **#162**（「空实例整轮」门禁：让 `verify:lab` 能对着
自起的空实例跑全部套件，并普查修掉所有吃环境数据的判据）。两件事的边界：
本条管「干净实例上装不装得起来」（这条缺口以前没有任何门禁盖得住），#162 管
「全部套件的判据自足性」。**#162 要起自己的干净网关时直接复用 `freshGateway.ts`
的 `startFreshGateway()`**，别再写第二份。

已知的「只有空实例上才红」的既有条目（归 #162，不属本条）：F-01 的 chat 树官方
右栏三条断言要网关上有一条非空白会话才量得到（`rightbarOpenChecks` 那一段已经会跳过，
F-01 主体里那三条还没有）；F-41 / F-49 等按 #162 的普查结论处理。

**CI 里不跑这个套件**（它需要本机跑着一个真网关），它是开发/合入前的本机第一道验证。

### 干净 profile 门禁（`npm run verify:clean-profile`，#165）

上面那条连的是**你机器上那台日常网关**（插件几十个、会话上千）。还有一条**自起实例**的门禁，
验的是另一种环境：在临时目录里开一个全新的 `DSH_HOME`，按 `docs/plugin-packages.md` 的方式把
`packages/` 下的自有插件包装进 profile，再起一个独立端口的 dsh，然后用本实验室这套装配页
（`labServer.ts` 的 `startLabServer` + `wireFilter` + `assemblyMirror`）逐棵树打开，核对
「干净 profile 上装配页能起来」。它不读 `~/.dsh/dsh-owned.json`、不碰你正在跑的那台实例，
跑完按 PID 收掉自己起的进程。

**为什么要单列一条**：干净 profile 与日常实例差两件要命的事——① 把自有插件包装进 profile 之后
插件总数多五个，官方按 combo URL 的长度上限把插件清单**切成两批**（实测 2026-09-17：日常实例
一批 55 条，装了自有插件包之后 59 + 1 两批，第二个批里正是 `directory-picker-native`），
过滤只看第一批时会误判成「清单对不上」而整页打不开；② 网关清单里已经有同 id 的自有插件时，
装配侧再叠一份本地 bundle 会让客户端抛 `duplicate graph entry`。两件都只在「干净 profile +
装了自己的包」这个组合上出现，日常实例上照不出来。门禁先断言**前提**（wire 真的被切成两批），
前提没了会红——免得这条门禁哪天变成空的。

已知阻断项写在脚本的 `KNOWN_BLOCKERS` 里（每条带 issue 号与报错签名，签名不符即失败）：
侧栏树现在还被 #164 挡着（官方 `ui-model-selection` 等 `ui-commands` 的 `commandUi`）。

**不在本实验室覆盖内的两页**：安装引导 tab 与侧栏状态页（`src/ui/installGuide.ts`、
`src/ui/sidebarStatusPage.ts`）是宿主侧普通 HTML——dsh 没装或服务没起来时网关不通，装配页组装不了，
它们不参与装配树。这两页的冒烟在 `test/install-guide/`（`npm run verify:install-guide`，
也是 Playwright 跑普通浏览器页面，不需要网关），跑法与断言清单见那个目录的 README。

产物（都已 gitignore，随时可重跑）：

- `test/assembly-lab/out/verify.lab.ledger.json`——台账（事实源，报告由它渲染）
- `test/assembly-lab/out/verify.lab.report.html`——单文件报告（截图 base64 内嵌，可直接分发）
- `test/assembly-lab/out/shots/*.png`——各套件截图
- 连外部实例那一轮（`--gateway`）的产物想单独放就用 `--out <dir>`。

人工开窗：跑 `--headed --keep`，浏览器打开的 `/` 是实验室首页，列出四棵树的页面链接。
`--keep` 时**隔离实例也一起留着**（不留的话那几个页面就没有数据面了）——它是唯一不清场的一档，
Ctrl-C 仍会把实例与临时目录收掉；报告里的 R-06 会把这一档如实记成「故意留着」而不是残留。

## 「只读」与「不动用户机器」是什么意思（#98 / #163 / #177）

写套件的人先看这一节。两条边界，别混为一谈：

- **实例数据这一层**：默认跑法连的是**实验室自起的隔离实例**（临时 `DSH_HOME`、运行期
  可写、跑完收掉），所以「不写网关数据」在默认跑法下**不成立也不需要**——播种就是往里写。
  真正要守的是「**整轮零请求打到实例之外**」，由 **R-06** 每次整轮兜底（页面请求的源逐个
  核过 + 对用户日常实例只做只读探测）。`--gateway` 连外部实例时，这一层恢复成字面意义的
  **只读**（不喂 prompt、不建会话、不归档、不改名、不写它的设置文档）。
- **用户机器这一层**：**永远**不许对任何网关派发会触发原生副作用的动作——实例是一次性的，
  机器不是。这一层是三条可执行的边界：

2. **不动用户环境**（原生副作用，两种跑法都不许）：**不得对网关派发会触发原生副作用的动作**。这类动作的后果是
   用户桌面上的一个窗口或一个进程：#163 的现场就是交互活性探针点了官方会话头那枚
   「在访达中打开工作目录」——官方 UI 收到点击后往网关发 `POST /open-in-app/open`
   （带上要打开的应用与工作目录），网关宿主再跑 macOS 的 `open <工作目录>`；实验室连的
   是用户真机上的网关，于是**每跑一轮整轮就在用户桌面上拉起一次访达**，用户看到的是
   「怎么总是有个进程用 Finder 打开文件夹」。同一类的还有：开终端、开外部浏览器、用
   系统默认应用打开文件（设置页那条「打开配置文件」的官方实现就是它）、原生文件对话框
   （打开文件 / 选目录）。

   **这一层由两条并存的规则守着**（#163 与 #175 各管一头，缺一条都不闭环）：

   - **#163 管「不许点」**：`livenessSuites.ts` 里那些会落到用户机器上的交互点，标
     `observeOnly` 并且**一步都不点**（每条写清理由）。这条是人一条条列出来的——枚举漏
     一个就漏一个，所以它是「预防」，不是「判据」。
   - **#175 管「点了也必须当场红」**：整轮里**任何一页**发出的请求，只要命中
     「会打到用户机器」那几条路由，**整轮红**（R-06 的一条断言），失败信息报出**套件、
     页面、路径与参数摘要**。这份路由表在 `harness.ts` 的 `NATIVE_SIDE_EFFECT_ROUTES`，
     逐条带官方出处：`/open-in-app/open`（拉本机应用）、`/api/settings/openSettingsDocument`
     （系统默认应用开文件）、`/api/settings/openAgentPresetDirectory`、
     `/api/session/openWorkspacePath`、`/api/directoryPicker/pick`（原生选目录面板）、
     `/api/terminal/create`（在用户机器上起一个真 PTY）。观测点包在 `Browser` 那一层
     （`launchBrowser` → `observeEveryPage`），所以**套件自己 `newPage()` 开的页也扫得到**
     ——官方页、`/official` 页、裸上下文里造的页都在内，不靠「记得经过 `openTreePage`」。
     判据只看 POST：官方那两条通道都只认 POST，非 POST 到不了原生动作，记成红只会是假红。
     参数只记**摘要**（键名与值的形状，字符串只给长度），绝不把用户路径灌进报告。
3. **不动用户的持久状态**：点一下会改用户设置或会话的控件同样不许点，例如设置页的
   「增大字号」（官方 ui-theme 点一下就经网关把新字号写进用户的设置文档）、空草稿时的
   「发送消息」（真按下就是给会话发一条消息）、回收站计数不为 0 时的「清空」（终点动作，
   不可恢复）。默认跑法连的是一次性实例，**写它**本身不违规；这一条管的是**控件不许点**，
   因为「点了会写」这件事在 `--gateway` 连外部实例时后果一样。

**整轮到底发了哪些网关调用**：R-06 的报告说明里有一张表（方法名 / 次数 / 归类）。归类按
**默认从严**：方法名末段按 camelCase 切成词，命中读词表（`list` / `get` / `read*` /
`describe` / `follow` / `search` / `inspect` / `inventory` / `catalog` / `can…` 这些）算读，
**其余一律按写算**；写类里名字不在已知写词表里的标「写（新面孔）」当场点名。这样官方明天
新增一个方法时，它不会两边都不沾地静默消失。

**怎么复现 #175 那条判据红**（负向对照，任何一轮都能重做，**不会真拉起访达**）：某个套件里
临时加一句页面侧调用，把 URL 指到一个**没人监听的 loopback 端口**上（现取一个空闲端口再关掉
即可），路径写 `/open-in-app/open`；请求会被观测层看见、又到不了任何网关，所以判据当场红
而用户桌面上什么都不会发生。撤掉即绿。走这条而不是真发一次，是因为自起的隔离实例**也**是
用户这台机器上的真 `dsh web`——真发一次就是真的拉一次访达。

**这类控件怎么覆盖**（二选一，都不许「为了覆盖而真点」）：

- **只观察**：`livenessSuites.ts` 里的 `observeOnly`。这一类交互点只判「控件在场（可见、
  几何非零）」、（声明了期望时）「当前是禁用态」、以及「这一步没有派发过任何点击」，几何与
  禁用态记进事实；每条必须写清**为什么不点**。判据里「没有派发过点击」不是靠自觉，是页面侧
  数出来的（观察窗口内收到真实 click 就判红）。
- **假宿主 + 契约断言**：动作走**宿主能力口**的那些（设置齿轮、工作区行的「终端打开 /
  在 VS Code 打开」、「在新标签页打开」、导出、外链、git 卡片）在实验室里由假宿主
  （`fakeHost.ts`）接住，只被记录、不落地——这些照常点、照常断言。

**#163 的普查结论**（全实验室范围，逐类给结论）：

| 类别 | 有哪些 | 处置 |
| --- | --- | --- |
| 点官方 UI、动作经真网关落到宿主（原生副作用） | 会话头的「在访达中打开工作目录」（`dsh-client-ui-open-in-app` 的分裂按钮，我们那页与官方页各点一次 = 每轮两次） | **改成只观察**（#163 那一改）；改前实测每轮两次 `open <工作目录>`，改后实测 0 次 |
| 点官方 UI、动作经真网关落到宿主的其它入口（本轮清单里没有，将来也不许加进去点） | （a）`＋` 菜单里那个「文件」候选（`dsh-client-ui-conversation` 的 `pickFiles` 注释就是「Open the native file dialog」）；（b）chat 树里官方那道「添加工作区」的原生目录选择器（`dsh-client-ui-directory-picker-native`，只在侧栏 / 设置两棵树的 block list 里）；（c）交付物卡片行尾的「打开 / 在访达中显示」（`dsh-client-ui-deliverables` → 网关宿主按 `openWorkspacePath` 打开）；（d）右栏的官方终端那一族（`dsh-client-ui-sidebar-terminal` 的引导入口点开就是 `webTerminals.launchShells` = 在宿主上开一个真 shell；本轮实测右栏页签只有「对话 / 轨迹 / 开始」，终端那一条没渲染出来——它一旦出现在页面上，同样只许看、不许点） | 探针只点到「开菜单 / 开页签」为止，**不选候选、不点卡片按钮**；要覆盖这些动作就用假宿主 + 契约断言，不许真点 |
| 点官方 UI、动作经真网关写用户的持久状态 | 设置页「增大字号」（写用户设置文档）、「打开配置文件」（`settings.action` 这个 slot 里官方那条由网关宿主用系统默认应用打开 `~/.dsh/settings.yaml`；我们那条走宿主能力口，两枚同一个 slot、官方那条靠一条自有 CSS 藏起来） | 两条都**改成只观察**（#163） |
| 点官方 UI、动作留在客户端 | composer 的 ＋ / 权限 / 模型 / 上下文用量、对话区页签、右栏开合、官方搜索栏、消息反馈弹层（点它开的是客户端弹窗；**已知写路径走不到**：已经点过赞的那条消息上这枚按钮的 `aria-label` 是「取消标记」，探针的选择器命中不到它） | 照常点（原来就在点，判据不变） |
| 点官方 UI、动作是在真网关上「打开会话」 | 点会话行（F-46 ⑥ 在官方页点、F-22 在我们树上点）——这条会真的到网关开那条会话，与页面加载本身打开会话是同一件事（F-47 记录过：点到一条正被别的 dsh 进程占着的会话会拿到 `SessionAlreadyOwnedError`） | 保持现状：不写用户数据、不开原生应用，R-06 用「会话数不变」兜这一层；点哪一条要意识到它会被打开 |
| 我们自己的写操作 | 归档、回收站、分组、标签组、改名、拖拽落盘 | 一律落在假宿主的内存表（`fakeHost.ts` 的 `stateStore`）或页内夹具的回执上，不碰 `~/.dsh`；确认弹窗一律只取消、不确认 |

改这套纪律之后，F-54 的交互点表里五条走「只观察」（会话头的访达按钮、设置页的
「打开配置文件」与「增大字号」，以及本来就点不动的两条禁用态：空草稿的发送、回收站计数 0
时的清空）。**人工验收这条改动**：跑整轮时盯一眼桌面上有没有 Finder 窗口被拉起来
（或跑之前 `ps -eo pid,command | grep -i finder | wc -l` 记一次、跑完再比），改后应当没有。

## 收尾与退出码（#88）

这个套件常被几个并行开发 session 同时跑，所以「跑完自己退、退出码就是真实结果、
结束后不留东西占着端口」是硬要求——过去它偶发跑完不退出（#88 现场实测：一台机器上
堆了 38 个挂着不动的 `verify.ts` 进程，0% CPU，只能靠人按特征去清）。

- **退出码**：`0` = 全部通过；`1` = 有断言失败（套件跑完了，结果就是红的）；`2` =
  起不来或未预期失败；`130` / `143` = 被 Ctrl-C / SIGTERM 打断。
- **端口被占立刻失败**：实验室端口（`LAB_PORT`）被别的进程占着时不再静默挂住，而是
  直接报出占用者的 pid 与命令行，并以 `2` 退出。换端口用 `LAB_PORT=<n> npm run verify:lab`。
- **被打断也收干净**：Ctrl-C / SIGTERM 会先关掉 chromium、实验室服务器与**隔离实例**
  （按 PID）再退，临时 `DSH_HOME` 一并删掉，不留孤儿进程、不留临时目录。这条要求
  `chromium.launch()` **关掉 Playwright 自己的 `handleSIGINT` / `handleSIGTERM`**
  （`harness.ts` 的 `launchBrowser`）：它默认收到 SIGINT 会自己关浏览器然后
  `process.exit(130)`，我们的收尾刚走到 `browser.close()` 就被它带走——#177 实测过这个现场
  （进程按 130 退出，隔离实例与临时目录原地留下），收尾只能有一个主人。
- **跑完不留残留**：mirror 转发出去的流式连接（网关的 `/plugins/events` 不会自己结束）
  收尾时会显式断掉；实验室自己的两个监听端口也一并关掉。
- `--keep` 是唯一例外：它故意把实验室服务器留着给人点页面，所以跑完不退出（此时
  Ctrl-C 仍会把服务器收掉）。

## 套件

下文各行里写的「真网关**只读**」，在**默认跑法**下指的是**实验室自起的隔离实例**（一台真的 dsh
进程，只是数据目录与端口都是本次运行现造的、跑完就收）——那是「没写进用户 `~/.dsh`」的意思，
不是「没有写操作」：默认跑法里套件可以写那台实例（播种就是这么干的）。`--gateway` 连外部实例时，
这些行按字面读：**只读**（不写那台实例的数据，也不点会落到用户机器上的控件）。

## 页面是怎么造出来的（为什么可信）

`labServer.ts` 不用自己那份 HTML 模板，而是直接调生产模块：

- 装配页 HTML = `src/ui/assembly/pageHtml.ts`（与 VS Code webview 里同一个函数）；
- 清单过滤 = `src/ui/assembly/wireFilter.ts` + `src/ui/assembly/trees.ts`
  （三棵树的 block list / 自有插件 id，与生产**同一份定义**）；
- loopback 反代 = `src/server/assemblyMirror.ts`（与扩展里同一个 mirror 实例实现）；
- 页面其余请求（`/plugins-local/??…`、`/api/…`、`/assets/…`）原样转给 mirror，
  实验室不自己造资产管线。

所以「实验室验的就是生产装的」不是靠人工同步，而是同一份代码。

四棵树：`/chat`、`/sidebar`、`/sidebar-official`（对照档：同一 frame 不装自有树插件，
让官方浏览区渲染，供 PARITY 当基准）、`/settings`。

页内宿主是**假宿主**（`fakeHost.ts`，走 `addInitScript` 在页面任何脚本之前注入，对应
「VS Code 在 webview 里预置宿主对象」的真实位置）：`acquireVsCodeApi` 与 VS Code 同语义
（**全页只允许一次**，第二次 throw），`dshOne.hostCall` 按 `src/pure/hostCalls.ts` 的同一套
协议应答（按能力各记观测值：`openedUrls` / `sessionTabsOpened`）。

开页默认**一页一个浏览器上下文**（各自干净 localStorage）；要造「真 VS Code 里多条
webview 同源、共享 localStorage」的现场（多开会话 tab 的互相干扰就发生在这里），用
`openTreePageAlongside` 在已有页面的同一上下文里再开一页（F-08 MULTIOPEN 就是这么验的）。

- **崩溃与缺失契约永远不准进白名单**：`KNOWN_NOISE` 只放行与底座无关、且另有 issue 跟踪的
  官方插件噪音，每条必须写理由与 issue 号（现有 1 条 = #74）。
- 交互夹具（例如「消息正文里的 commit hash」）允许页内注入，但必须在套件的 `expect`/注释里
  说明为什么用夹具而不是真数据（真模型输出不可复现）。
- 只用**官方语义标记**选元素（slot 属性 `[data-slot=…]`、`role`、自有类名）；官方 CSS-module
  的哈希类名一律按**类名后缀**匹配（`_sessionRow`），不写死哈希前缀。
- **判官方组件的落点先读官方源码，把官方的约束一起建模**：不要只算「锚点 + 间距」就断言——
  官方算出落点之后还会按视口再收一次（例：官方 `Menu` 把整份菜单钳进视口、四周各留 12px），
  这条约束也要照抄进判据。出处、常数与两种落点的判法写在 `suites.ts` 的 `officialMenuPoint`
  上面（#159 就是漏了它，行一靠下就红）。同理，菜单高度这类「随项数变化」的量要从菜单自己量，
  别写死。
- 一次性诊断脚本不入库：跑完就删，或改造成可复跑的套件后再提交。
