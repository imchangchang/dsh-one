# Backlog：遗留问题与未来事项

记录已知但未解决的问题、待做的改进和将来可能要做的事。

## 约定：文件夹即索引

- **一个条目一个文件**，文件名用语义化 kebab-name（如 `mux-reconnect.md`），不带序号/日期前缀——编号要"取当前最大 ID + 1"，并发 session 会撞号。
- **状态用文件夹表达**，改状态就是 `git mv`，不动文件内容：
  - `open/`：未做、进行中、部分完成的条目都在这里；
  - `closed/`：已解决的条目，解决时 `git mv` 进去。
- **不维护任何手工索引表**——`ls docs/backlog/open` 就是当前待办，避免多进程/多 worktree 并发编辑同一文件造成合并冲突。
- **准入：提出 ≠ 修改**——提需求要澄清并确认做法，提问题要核实并定位根因，产出写进条目后就停下，不顺手改代码；方案/根因未定的想法级条目可以进 `open/`（正文注明「想法：未确认」），但修改动作只有被明确要求时才做。
- 条目内容应包含：背景与现象、根因或现状、建议方案、涉及代码位置。有前置依赖时在正文写一行「前置：kebab-name」。
- `closed/` 只进不出，定期（每季度或文件数明显碍事时）把旧条目汇总成一个归档 md 后删除原文件。
