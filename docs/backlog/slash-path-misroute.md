# 粘贴以 / 开头的绝对路径会被当成斜杠命令

记录于 2026-09-27。问题在 dsh-one 自身代码。

## 背景与现象

用户反馈：在输入框粘贴 macOS 绝对路径（如 `/Users/cgeng/Downloads/xxx.svg`，后面还跟着中文提问），整条消息没有发给模型，而是收到「未知或格式错误的命令：/Users/…」的提示。截图已确认。

## 根因

发送路由只看首字符：`chatView.ts` 的 `send` 分支里 `text.trim().startsWith('/')` 即走 `runCommand`（约 1025 行），`executeCommand` 匹配不到任何已知命令时回「未知或格式错误的命令」（约 1215 行）。注释里写这是「与官方 web composer 相同的路由」，但官方行为未实测核实，粘贴路径这个场景在本扩展里必定误伤。

另外 `webview.ts` 的斜杠命令弹窗（约 429、1032、1184 行）也是同款判断，输入 `/Users/…` 时会弹出命令补全，属于同一问题的表现层。

## 建议方案

路由前先看第一个 token 是否像命令：以 `/` 开头且第一个空白前不含第二个 `/`（即不是路径），才走 `runCommand`；否则按普通 prompt 发送。这样 `/permisison` 这类命令笔误仍走「未知命令」提示，`/Users/…` 这类路径正常发给模型。webview 侧的弹窗触发条件同步收窄。

## 涉及代码位置

- `src/ui/chatView.ts`：`send` 分支的路由判断（约 1023-1028 行）、`runCommand` 的未匹配提示（约 1213-1217 行）。
- `src/ui/chat/webview.ts`：斜杠弹窗触发判断（约 429、1032、1184 行）。
